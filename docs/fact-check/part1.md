## Patterns

- **Cut excerpts lose qualifiers.** Shortening with "..." dropped hedges that change the meaning: "For example," and "only when user consent is enabled" (MS c12), and "should" vs "need" (GH c17). The excerpts were real quotes, but the claim text was stronger than the source.
- **Claims based on missing information** (GH c2, c20; Google c22) were labelled honestly as partially_supported, unverified or inference. Firsthand evidence helped exactly there. It also caught one overstatement: GitHub does show new-app trust signals.
- **Google's cap wording is spread across pages.** The help pages tie the cap to "unverified app screen" or "testing/staging". Only the console text links it explicitly to unapproved sensitive or restricted scopes.
- **Page summaries can differ from the body.** The brand-verification summary says "2-3 business days", while the body says the automated path takes minutes. The guide quotes the body correctly.
- **Big pages need targeted extraction.** The Graph permissions reference (about 578k characters) was cut off by WebFetch before the Mail.Read row, so I checked it from the raw HTML. A link alone can't show the row.
